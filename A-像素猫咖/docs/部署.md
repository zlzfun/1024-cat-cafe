# 部署

把 1024 猫咖挂在一个已有网站的 `/1024-cat-cafe/` 下：同事打开 `https://网站的地址/1024-cat-cafe/` 就能进店、联机、集章、登记抽奖。

猫咖是一个 Node 进程，零依赖，只听本机（`127.0.0.1:1024`），网页、接口、联机都走它；那个网站的 nginx 把 `/1024-cat-cafe/` 转给它。`A-像素猫咖/deploy.sh` 把启动、装成服务、生成 nginx 那一段、经过网站验一遍、备份、打离线包都包好了。它不改 nginx，也不碰服务器上别的东西（见"和别的服务共用一台服务器"）。

**照着部署的，先看下一节**：一步一步的命令、每一步该看到什么、什么时候停下来问人。后面各节是为什么这样做、出了问题怎么查。

## 给执行部署的 agent：照着做

**原则**

- 服务器和网站是别人的。只做这里写到的改动：在网站对外的那个 `server { }` 里加一行 `include`，新建 `snippets/1024-cat-cafe.conf`，人同意的话装 systemd 服务 `cat1024`。别的 nginx 配置一个字不改：不加 `map`、`upstream`，不动 `http { }`、别的 `server { }`。
- nginx 只用 `nginx -t` 和 `reload`，不用 `restart`、`stop`。
- 不改防火墙、SELinux、别的服务、系统里的 Node；要改，停下问人。
- 看到的和这里写的对不上，或者遇到这里没写的情况：停下，把命令和输出原样告诉人，别自己想办法绕过去。
- 后台口令、抽奖登记的个人信息只私下交给人，别贴到群里、工单里。

**开始前问清楚**（缺哪样问哪样）

| 要什么 | 例子 | 用在哪 |
|---|---|---|
| 网站的地址 | `https://portal.example.com` | 猫咖的地址就是它后面加 `/1024-cat-cafe/` |
| 能不能用 sudo、能不能改这个网站的 nginx | | 第 5～7 步改 nginx、第 9 步装服务都要 sudo。不能的话，把这几步的命令交给人做 |
| 内源主页的地址 | | `--inner`。不知道可以先空着，以后 `./deploy.sh start --inner '…'` 补上（不用重启） |
| 代码在哪 | `~/1024-cat-cafe` | 人给的离线包解开的目录，里面有 `deploy.sh`、`index.html`、`server/` |

下面命令里的 `portal.example.com` 换成网站的域名，`~/1024-cat-cafe` 换成代码目录；`./deploy.sh` 都在代码目录里执行。

**第 0 步：检查环境**

```
cd ~/1024-cat-cafe
./deploy.sh check
sudo -n true && echo sudo-ok
sudo nginx -t
```

该看到：`✓ Node v…`（18 以上）、`✓ 端口 1024 空着`；`sudo-ok`；`syntax is ok`、`test is successful`。

- 没有 Node，或者版本太旧：要一个带 Node 的离线包（见"离线包"），问人要。
- 端口被占：换一个没人用的，第 1 步加 `--port 1025`。
- 没有 `sudo-ok`：sudo 要密码，第 5～7 步和第 9 步交给人。
- **改之前 `nginx -t` 就不通过：停下告诉人**（网站自己的配置已经有问题，这时候 reload 什么都不会生效）。
- 没有 `nginx` 命令，或者网站是别的机器、容器里的 nginx 发的：停下告诉人。

**第 1 步：启动猫咖**

```
./deploy.sh --data ~/1024-cat-cafe-data --inner 'https://内源主页的地址'
```

该看到：`✓ 开张了`，后面是地址、后台口令，和"接下来"的五条（下面第 3～8 步就是它们，写得更细）。数据放在单独的目录里，以后换代码不用搬。

**第 2 步：记下网站现在的样子**

```
curl -s -o /dev/null -w '%{http_code}\n' https://portal.example.com/
curl -s -o /dev/null -w '%{http_code}\n' https://portal.example.com/1024-cat-cafe/
sudo nginx -T 2>/dev/null | grep -c '1024-cat-cafe'
```

该看到：首页的状态码（记下来，第 8 步对比）；`404`（不是 404，说明网站自己在用这个路径：停下问人）；`0`（nginx 里还没有猫咖）。

curl 报 `Could not resolve host`：服务器上解析不了网站的域名，每条 curl 加 `--resolve portal.example.com:443:127.0.0.1`。报证书的问题：加 `-k`。

**第 3 步：找到网站对外的那个 server { }**

```
sudo nginx -T 2>/dev/null | awk '/^# configuration file /{f=$4; sub(/:$/,"",f)} /^[[:space:]]*(listen|server_name)[[:space:]]/{print f": "$0}'
```

每一行前面是文件，后面是它里面的 `listen`、`server_name`。找 `server_name` 里有网站域名、`listen` 有 `443` 的那一组（网站是 http 的，就找 `80`），那个文件下面叫"网站的文件"。同一个文件里常有两个 server 都写着这个域名：`listen 80` 那个只做跳转，要的是 `listen 443` 那个。找不到，或者有好几组都对得上：停下问人。

**第 4 步：备份网站的文件**

```
mkdir -p ~/nginx-backup-1024-cat-cafe && sudo cp -p 网站的文件 ~/nginx-backup-1024-cat-cafe/
```

备份别放在 `sites-enabled/`、`conf.d/` 里：那里的文件会被 nginx 一起读进去。

**第 5 步：装上猫咖那一段**

用第 1 步"接下来"第 2 条打印的那条命令。默认是：

```
sudo mkdir -p -m 755 /etc/nginx/snippets && sudo install -m 644 ~/1024-cat-cafe/nginx-1024-cat-cafe.conf /etc/nginx/snippets/1024-cat-cafe.conf
```

nginx 的配置目录不在 `/etc/nginx` 的（自己编的、OpenResty 这类），脚本已经按 `nginx -V`、`nginx -t` 换成了那台的目录；`./deploy.sh nginx` 随时再打一遍。下面都以 `/etc/nginx` 为例。

**第 6 步：在那个 server { } 里加一行**

加在第 3 步找到的那个 `server { }` 的 `listen … 443 …` 那一行下面（这一行只有对外的那个 server 有，不会加错地方；网站是 http 的，就加在它的 `listen 80` 下面）。先找行号：

```
sudo grep -n 'listen.*443' 网站的文件
```

有好几行的，用 `sudo sed -n '起,止p' 网站的文件` 看看各在哪个 server 里，取那个 server 的第一行 `listen`。比如是第 12 行：

```
sudo sed -i '12a\    include /etc/nginx/snippets/1024-cat-cafe.conf;' 网站的文件
sudo grep -n '1024-cat-cafe' 网站的文件
sudo sed -n '9,16p' 网站的文件
```

该看到：`1024-cat-cafe` 只出现一次，就在第 13 行，前后是那个 server 自己的 `listen`、`server_name` 这些。只加这一行，只加在这一个 server 里。

**第 7 步：检查、生效**

```
sudo nginx -t && sudo systemctl reload nginx
```

该看到：`syntax is ok`、`test is successful`，reload 不报错。nginx 不归 systemd 管的，用 `sudo nginx -s reload`。

**`nginx -t` 不通过**：把第 4 步的备份拷回去，删掉 `/etc/nginx/snippets/1024-cat-cafe.conf`，再 `sudo nginx -t` 确认恢复了；停下告诉人。

**第 8 步：经过网站访问一遍**

```
./deploy.sh verify https://portal.example.com
curl -s -o /dev/null -w '%{http_code}\n' https://portal.example.com/
```

该看到：verify 每一行都是 `✓`，最后一行 `全部正常`（gzip 那一行是 `!` 也可以）；首页的状态码和第 2 步一样。

```
经过 https://portal.example.com/1024-cat-cafe/ 访问一遍：
  ✓ 网站首页 https://portal.example.com/：200
  ✓ /1024-cat-cafe → 301 https://portal.example.com/1024-cat-cafe/
  ✓ /1024-cat-cafe/：200
  ✓ 用的是 deploy.sh 生成的那一段（有 X-1024-Cat-Cafe 头）
  ✓ 没带上网站的 Content-Security-Policy
  ✓ /1024-cat-cafe/api/health：{"ok":true,"cats":0,"online":0,"up":42}
  ✓ /1024-cat-cafe/js/app.js：200
  ✓ 脚本压缩传（gzip）
  ✓ 联机 /1024-cat-cafe/ws：101
  ✓ 组织者后台的接口：200
全部正常
```

- 服务器上解析不了网站的域名：`./deploy.sh verify https://portal.example.com --via 127.0.0.1`（直接连本机的 nginx）。
- 有 `✗`：它下面 `→` 后面写着该查什么，详见"出了问题"。改完再 `nginx -t`、reload、verify。修不好，就按第 7 步的办法把网站恢复原样，停下告诉人。
- verify 会把网站的地址记进 `deploy.env`，以后 `./deploy.sh status` 也会经过网站查一下。

**第 9 步：装成服务**（人同意的话；服务器重启以后会自己起来）

```
./deploy.sh service
./deploy.sh status
```

该看到：`✓ 装好了`；status 里有 `在跑（systemd 服务 cat1024）`、`接口正常`、`网站的 nginx 装的就是这一段`、`经过网站（…）：接口正常`。

**第 10 步：交给人**

- 店：`https://portal.example.com/1024-cat-cafe/`；后台：`https://portal.example.com/1024-cat-cafe/admin.html`，口令在 `~/1024-cat-cafe-data/admin.key`（私下给）。
- 改了什么：网站的文件里加的那一行（文件名、行号）、新建的 `/etc/nginx/snippets/1024-cat-cafe.conf`、`/etc/systemd/system/cat1024.service`（装了的话）；备份在 `~/nginx-backup-1024-cat-cafe/`。
- 请人用两台电脑的浏览器打开店的地址：都能进店，在店里看得到彼此；点门厅的迎宾立牌，"内源主页"打得开。
- 人测完以后，清掉测试留下的猫和登记：`printf 'RESET\n' | ./deploy.sh reset`（会先自动备份一份）。

**撤掉**（人要求的时候）

```
sudo cp -p ~/nginx-backup-1024-cat-cafe/网站的文件名 网站的文件     # 或者只删掉 include 那一行
sudo rm /etc/nginx/snippets/1024-cat-cafe.conf
sudo nginx -t && sudo systemctl reload nginx
./deploy.sh uninstall
```

`uninstall` 停下猫咖、拆掉服务，代码和数据留着。数据目录里有抽奖登记的个人信息，删不删问人。

**升级**（人给了新的离线包）

解开到一个新目录，从旧目录拷来 `config.js` 和 `deploy.env`，然后在新目录里：装过服务的，`./deploy.sh service`（服务换到新目录，会提醒一声）；没装服务的，先在旧目录 `./deploy.sh stop`，再在新目录 `./deploy.sh`。再 `./deploy.sh status`：端口没变，会说"网站的 nginx 装的就是这一段"，nginx 不用碰；说"不一样"，照它给的命令更新。最后 `./deploy.sh verify`。

**别用**：`./deploy.sh logs -f`（一直跟着看，不会自己结束），用 `./deploy.sh logs`。

## 要什么

- **网站所在的那台服务器**：猫咖和网站的 nginx 放在同一台上最简单（nginx 在另一台机器上也行，见下面参数里的 `--host`）。Linux；macOS、Windows 也能跑，只是不能装成 systemd 服务。
- **Node 18 以上**（压测脚本要 22 以上）。服务器上没有、又上不了外网：在能上网的电脑上打一个带 Node 的离线包拷过去（见下面"离线包"）。
- **本机的一个端口**，默认 1024，只给 nginx 用：不用开防火墙，也不占网站的 80、443。
- **能改那个网站的 nginx 配置**（或者找管它的人）：在它的 `server { }` 里加一行 `include`。

### 配多大的机器（2026-10-08 用现在的代码实测）

压测在一台 Apple M5 Pro 上跑（服务端和假玩家在同一台；见[联机](联机.md)第七节）。一般云服务器的一个核比它慢两三倍，下面"建议"已经按这个留了余量：

| 同时在线 | 服务端 CPU（M5 一个核） | 内存 | 服务端发出 | 每个浏览器收 |
|---|---|---|---|---|
| 100 只 | 3～5% | 66MB | 0.3～0.6MB/秒（约 3～5Mbps） | 4～7KB/秒 |
| 200 只 | 7～8% | 88MB | 1.6～2.4MB/秒（约 13～19Mbps） | 8～12KB/秒 |
| 400 只 | 12～14% | 133MB | 6～9MB/秒（约 50～73Mbps） | 15～25KB/秒 |

- **建议**：同时在线 200 只以内，1 核、1G 内存、1G 磁盘、20Mbps 出口就够；300～600 只，2 核、2G、100Mbps。服务端最多收 600 条连接。
- **真正先吃紧的是带宽**，不是 CPU：每只猫要把画面里别的猫的动作发给它，人越多、越挤，每人收得越多。猫咖和网站共用一个出口，人多的时候要掂量。
- **网页本身**：第一次进店每人下载约 1.3MB（56 个脚本、页面和 130KB 的像素字体）；nginx 那一段开了 gzip，降到约 650KB。再来只问一声"改过没有"，没改就用浏览器里的（页面本身每次都重新拿，几十 KB）。活动刚开始大家一起进店时，比如 200 人一分钟内进来，是一百多 MB 的突发流量。
- **磁盘和存档**：名册是一个 JSON 文件，玩得很满的一只猫约 5.4KB（1000 只约 5MB，3000 只约 16MB）。每次有人存档就整份重写（0.2 秒合并一次），登记的猫越多，每次重写越慢：3000 只在 M5 上整份序列化一次要 50 毫秒左右，慢一点的服务器要 100 多毫秒，这期间联机会顿一下。登记的猫超过一两千只，建议把合并的间隔调长（`server/store.js` 的 `save`）。

## 一键启动

```
cd A-像素猫咖
./deploy.sh --data ~/1024-cat-cafe-data --inner 'https://内源主页的地址' --bots 40
```

它会依次：

1. 检查 Node 的版本（找不到就看 `runtime/node`，离线包里带的就在那儿）。
2. 写 `config.js`：内源主页的地址、补位机器人的数量。内源主页是内网地址，只写在这个文件里，它不进仓库。以后再启动不带这两个参数，就不动它；带了，只改这两项，文件里你自己加的别的设置原样留着。
3. 建数据目录（只有自己能读）。`--data` 指到的目录里有别的东西，就停下、不碰它。
4. 检查端口有没有被占（被占就不启动，不抢别人的），在后台启动，只听本机，等接口应答（`/api/health`）。
5. 生成 `nginx-1024-cat-cafe.conf`：挂到网站 `/1024-cat-cafe/` 下的那一段 nginx 配置，端口按现在的。
6. 打印对外的地址、组织者后台的地址和口令；网站的 nginx 还没装上那一段、这一段又是新生成的（第一次、换了端口），再打印装的步骤；装过了，就看装的是不是最新的。

```
✓ Node v20.17.0（/usr/bin/node）
✓ 写好了 config.js（内源主页：https://…，机器人：40）
启动：PORT=1024 HOST=127.0.0.1 DATA_DIR=/home/you/1024-cat-cafe-data TRUST_PROXY=1
✓ 开张了

  店：      https://网站的地址/1024-cat-cafe/          （nginx 加好那一段以后）
  后台：    https://网站的地址/1024-cat-cafe/admin.html    口令：…
  本机检查：http://127.0.0.1:1024/          （只有这台服务器自己打得开）
  nginx 那一段：/home/you/1024-cat-cafe/nginx-1024-cat-cafe.conf
  数据：/home/you/1024-cat-cafe-data    日志：/home/you/1024-cat-cafe/.run/server.log

接下来：把猫咖挂到网站的 /1024-cat-cafe/ 下（脚本不改 nginx：这几步你来，或者交给管这个网站的人。详见 docs/部署.md）
  1. 找到网站对外的那个 server { }（https 的那个；只做 80 转 443 的那个不用管），把它所在的文件备份到别处（别放在 sites-enabled、conf.d 里）
  2. sudo mkdir -p -m 755 /etc/nginx/snippets && sudo install -m 644 /home/you/1024-cat-cafe/nginx-1024-cat-cafe.conf /etc/nginx/snippets/1024-cat-cafe.conf
  3. 在那个 server { } 里加一行（listen 443 那一行下面就行）：include /etc/nginx/snippets/1024-cat-cafe.conf;
  4. sudo nginx -t && sudo systemctl reload nginx（-t 没过就别 reload；别用 restart）
  5. ./deploy.sh verify https://网站的地址
  撤：删掉 include 那一行和 /etc/nginx/snippets/1024-cat-cafe.conf，再 sudo nginx -t && sudo systemctl reload nginx
```

后台口令第一次启动时生成，存在数据目录的 `admin.key` 里。

**参数**（都可以不写；写过一次的端口、监听地址、数据目录记在 `deploy.env` 里，下次沿用；`--inner`、`--bots` 写进 `config.js`）。全部配置项、在哪儿改、改了怎么生效，见下面"配置项一览"：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port 1024` | 1024 | 本机端口。换了以后 nginx 那一段跟着重新生成，要把网站装的那一份换成新的（`./deploy.sh status` 会提醒） |
| `--data ~/1024-cat-cafe-data` | `server/data` | 数据目录：名册、抽奖登记、后台口令。建议单独一个目录（以后换代码不用搬）；里面不能有别的东西 |
| `--inner 地址` | 空 | 内源主页的地址，写进 `config.js`（服务在跑的时候也能直接改，大家刷新页面就生效） |
| `--bots 40` | 40 | 补位的机器人：这个数减去在线的真人数（最少留 12 只），写进 `config.js` |
| `--host 127.0.0.1` | 127.0.0.1 | 只听本机。nginx 在另一台机器上才用 `0.0.0.0`：再把 nginx 那一段里的 `127.0.0.1` 换成这台的地址，防火墙只对 nginx 那台放行这个端口 |

## 挂到已有网站的 /1024-cat-cafe/ 下

**域名和 IP 不用填**：猫咖的地址就是网站的地址后面加 `/1024-cat-cafe/`。网页里的接口地址是相对的，联机地址跟着网页走（`https://网站的地址/1024-cat-cafe/` 联机就连 `wss://网站的地址/1024-cat-cafe/ws`），服务端也不管访问它用的是哪个域名。要改的只有网站的 nginx：装上下面这一段，在网站的 `server { }` 里 include 它。

`deploy.sh` 生成的 `nginx-1024-cat-cafe.conf`（端口是默认的 1024 时就是这样；`./deploy.sh nginx` 随时再生成、打印一遍）：

```
# 1024 猫咖：挂在这个网站的 /1024-cat-cafe/ 下（deploy.sh 生成，猫咖的端口 1024）。
# 整段放进网站对外的那个 server { } 里，和别的 location 并列。每一行为什么在：docs/部署.md
# ^~：网站自己按后缀给静态文件的规则（location ~* \.(js|css)$ 这种）抢不走猫咖的文件
location ^~ /1024-cat-cafe/ {
    proxy_pass http://127.0.0.1:1024/;         # 结尾的 / 不能少：去掉 /1024-cat-cafe 再转给猫咖
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;    # 联机走 WebSocket，这两行不能少
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 600s;                   # 联机是长连接，别让 nginx 一分钟就掐断
    gzip on;                                   # 只管这一段：第一次进店的下载从约 1.3MB 降到约 650KB
    gzip_types text/css application/javascript text/javascript application/json image/svg+xml text/plain;
    # 这一段有了自己的 add_header，就不继承网站在 server 一级加的头（里面要是有 Content-Security-Policy，猫咖会白屏）
    add_header X-1024-Cat-Cafe 1;
}
```

**装上**（脚本不改 nginx：这一步你来做，或者交给管这个网站的人；一步一步的命令见上面"给执行部署的 agent"第 3～8 步）：

1. **找到网站对外的那个 `server { }`**：`server_name` 是网站的域名、`listen 443 ssl` 的那个。只做 80 转 443 跳转的那个不用管，加在那儿也不生效。
2. **先备份它所在的文件，备份放到别处**。别放在 `sites-enabled/`、`conf.d/` 里：那两个目录里的文件会被 nginx 一起读进去。
3. **把这一段装到 nginx 的 `snippets/` 下**：`sudo mkdir -p -m 755 /etc/nginx/snippets && sudo install -m 644 nginx-1024-cat-cafe.conf /etc/nginx/snippets/1024-cat-cafe.conf`。装一份 root 的，别直接 include 猫咖目录里的那份：那样谁能改猫咖的目录，谁就能改这个网站的 nginx。也别放进 `conf.d/`：那里的文件会被读到 `http { }` 一级，`location` 放在那儿 `nginx -t` 不通过。
4. **在那个 `server { }` 里加一行** `include /etc/nginx/snippets/1024-cat-cafe.conf;`（加在它的 `listen 443` 那一行下面就行，命令见"给执行部署的 agent"第 6 步）。先确认网站自己没在用 `/1024-cat-cafe/` 这个路径。
5. **检查、生效**：`sudo nginx -t && sudo systemctl reload nginx`。`-t` 没过就不会 reload，网站照旧；reload 是平滑的，正在访问网站的人不会断。别用 `restart`：配置有错的话 nginx 就起不来，整个网站都打不开。
6. **验一遍**：`./deploy.sh verify https://网站的地址`。

**撤掉**：删掉 include 那一行（或者拷回备份）和 `/etc/nginx/snippets/1024-cat-cafe.conf`，再 `sudo nginx -t && sudo systemctl reload nginx`。

**换了端口**（`./deploy.sh restart --port 8080`）：nginx 那一段跟着重新生成；`./deploy.sh status` 会说网站装的那一份"不一样"，并给出更新的命令（`sudo install …`、`nginx -t`、reload）。网站的文件不用再动。

**nginx 的配置目录不在 `/etc/nginx` 的**（自己编的 nginx、OpenResty 这类）：脚本先看 `nginx -V` 里的 `--conf-path`，没写就看 `nginx -t` 说的配置文件在哪，打印的命令里用的都是那个目录下的 `snippets/`。

### 这一段里每一行为什么在

- **`location ^~ /1024-cat-cafe/`**：`^~` 让这个前缀压过网站自己的正则规则。很多网站有 `location ~* \.(js|css|png)$ { expires 30d; }` 这种按后缀给静态文件的规则，没有 `^~` 的话 `/1024-cat-cafe/js/…` 会被它抢走：页面出来了，脚本全是 404。
- **`proxy_pass` 结尾的 `/`**：nginx 把 `/1024-cat-cafe` 去掉再转给猫咖。打开 `/1024-cat-cafe`（少了最后的斜杠），nginx 自动跳到 `/1024-cat-cafe/`。
- **`Upgrade`、`Connection`**：联机走 WebSocket，少了这两行进得了店、看不到别人。
- **`proxy_read_timeout 600s`**：联机是长连接，nginx 默认一分钟没动静就掐断。
- **`gzip`**：写在这一段里，只对猫咖生效，网站别的路径照旧。
- **`add_header X-1024-Cat-Cafe 1`**：nginx 的 `add_header` 是这样继承的：这一级只要写了一条，上一级的就都不继承了。所以网站在 `server` 一级加的头（常见的有 `Content-Security-Policy`、`X-Frame-Options`）不会套到猫咖上。猫咖的加载器是写在页面里的内联脚本，网站的 CSP 要是不许内联脚本，猫咖就停在"开门……"白屏。网站别的路径还带着它自己的头。想给猫咖也留哪个头，在这一段里再写一遍。这个头也是 `verify` 用来认"装的是 deploy.sh 生成的那一段"的。
- **没有 `map`、`upstream`、`server`**：这一段不碰 `http` 一级，也不碰网站别的路径。网上的 WebSocket 教程常让你在 `http` 一级加一段 `map $http_upgrade $connection_upgrade`，这里用不着，也别加：同名的 `map` nginx 不报错，后读到的那份会悄悄改掉网站别处的行为（实测：网站转给它自己后端的请求跟着变了，`nginx -t` 照样通过）。

### 网站的 server { } 里，这几样也会管到 /1024-cat-cafe/

| 网站里有 | 结果 | 怎么办 |
|---|---|---|
| 整站要登录（`auth_basic`、`auth_request`，比如接了公司的单点登录） | 进猫咖也要先登录；`verify` 在 `/1024-cat-cafe/` 那一步就报 302、401 或 403 | 本来就只给同事用，这样正好（verify 后面几步就请人在浏览器里验）；不想要：在装上的那一份里加 `auth_basic off;` 或 `auth_request off;`（之后 `status` 会一直说"不一样"，这是预期的） |
| `limit_req` 限得很紧 | 第一次进店要拉六十来个文件，超出的被拒（503），停在加载 | 请管网站的人放宽 |
| 在 `server` 一级写了 `return 301 …`（只做跳转的 server） | 这一段不生效 | 加到真正对外的那个 server 里 |

**定下网站的地址再开张，之后别换。** 每只猫的令牌存在浏览器里，是按网站的地址（域名、http 还是 https、端口）分开存的。开张以后网站换域名、从 http 换成 https，大家打开就是一只新猫，原来的猫、章都找不回来（它们还在名册里，只是浏览器认不出来了）。测试也用这个最终地址。

### 实测（2026-10-08，nginx 1.30.5）

在一份模拟"别人已有的 https 网站"的配置上，照"给执行部署的 agent"一节从第 0 步做到第 10 步，再撤掉。那个网站有 80 转 443 的跳转、`http` 一级的 `map` 和 `upstream`、按后缀给静态文件的正则规则、`server` 一级的 `Content-Security-Policy` 和 `X-Frame-Options`；服务器上解析不了网站的域名（curl 用 `--resolve`，verify 用 `--via 127.0.0.1`）：

- 第 3 步的命令列得出每个 server 的 `listen`、`server_name` 和文件；第 5 步脚本打印的命令里，配置目录按 `nginx -t` 换成了那台的；第 6 步的 `sed`（GNU sed 4.9）把 include 加在 `listen 443` 下面、缩进不乱；`nginx -t` 通过。
- `verify` 全部正常；网站原有的页面、静态文件、它自己的接口、80 转 443，状态、响应头、内容都和装之前一模一样，gzip 也没漫到网站别的路径。
- 浏览器经过这个 https 网站：两个浏览器都进店，联机走 `wss://…/1024-cat-cafe/ws`，在店里看得见彼此；后台页面用口令登得进去；页面没有报错。
- 换端口不更新网站那一份：重启时、`status` 都提醒"不一样"并给出命令，`verify` 报 502；照命令更新以后全部正常。
- 故意弄错，`verify` 都指得出来：没加 include（404）、去掉 `^~`（脚本被抢走）、去掉 `add_header`（带上了网站的 CSP，会白屏）、猫咖没在跑（502）。
- 另加一份同名的 `map`：`nginx -t` 照样通过，网站转给它后端的请求却变了。贴坏了（少一个 `}`）：`nginx -t` 报错；不看 `-t` 硬 reload，nginx 也不换配置，网站照旧。
- 撤掉：网站和最开始一模一样，`/1024-cat-cafe/` 又是 404；nginx 的 error.log 里没有意外的错误。

## 和别的服务共用一台服务器：会动到什么

`deploy.sh` 不改 nginx，也不碰防火墙、别的服务、系统里的 Node。它在服务器上放的东西只有这些：

| 什么 | 在哪 | 怎么撤 |
|---|---|---|
| 代码、`config.js`、`deploy.env`、`nginx-1024-cat-cafe.conf`、`.run/`（进程号、日志）、`backups/`、`dist/` | 猫咖自己的目录 | 删目录 |
| 数据 | `--data` 指的目录（默认 `server/data`，在猫咖的目录里） | 删目录（有抽奖登记的个人信息：要留先 `./deploy.sh backup`） |
| 一个 Node 进程，听 `127.0.0.1:1024` | | `./deploy.sh stop` |
| 一个 systemd 服务 `/etc/systemd/system/cat1024.service` | 只有跑了 `./deploy.sh service` 才有；这是脚本唯一用 sudo 改系统的地方 | `./deploy.sh uninstall` |

装进网站 nginx 的两样（`snippets/1024-cat-cafe.conf`、网站的文件里 include 那一行）是你（或者管网站的人）照步骤加的，撤的时候也从那儿删。

**不做的事**：不改 nginx（只生成那一段，打印装的命令）；不开端口、不改防火墙（只听本机，对外走网站原有的 443）；不装、不升级 Node，不跑 npm（零依赖，离线包带的 Node 在自己目录的 `runtime/node` 里）；端口被占就不启动；不建用户、不加定时任务、不碰别的 systemd 服务。

**防着出错**（都实测过）：

- **停之前先认一认进程**：进程号文件里的进程，要真是这个目录里的猫咖才停。进程号会被系统回收给别的程序；以前的脚本直接按进程号停，可能停掉别人的进程。
- **数据目录里有别的东西就不动**：`--data` 指到放着别的文件的目录，不启动、不备份、不恢复，也不改它的权限。
- **不覆盖别人的服务**：装服务时，`cat1024.service` 已经有了又不是猫咖装的，就不覆盖；是另一个目录里的猫咖，提醒一声再换过来。`uninstall` 只拆这个目录装的服务。
- **生成的文件只有自己读得到**：设置、日志、备份、数据都是只有这个账号能读（脚本的 umask 是 077）；后台口令不进日志（后台启动时日志里只写口令在哪个文件）。
- **用 root 跑会提醒**：猫咖只要能写自己的数据目录，用普通账号就行（要 sudo 的地方脚本自己会用）。
- **听 0.0.0.0 会提醒**：猫咖在 nginx 后面，按 nginx 加在 `X-Forwarded-For` 最后的地址认人（后台口令连错 10 次歇 10 分钟，按这个地址算）；能绕过 nginx 直连的话，别人可以自己编这个头。

**资源**：400 只猫同时在线，服务端在 M5 上用一个核的 12～14%、内存 130MB 左右，挤不着网站；可能挤着网站的是带宽（见上面"配多大的机器"）。

**同源**：挂在网站的路径下，浏览器把猫咖和网站当成同一个网站：localStorage、sessionStorage、没设 HttpOnly 的 cookie 互相读得到。猫咖只存 `cat1024` 开头的几项（你的猫的令牌、声音开关、本机模式的存档；后台口令在 sessionStorage，关了标签页就没了），不读 cookie。

## 日常

| 命令 | 做什么 |
|---|---|
| `./deploy.sh status` | 在不在跑、接口是不是正常、多少只猫、几个人在线；网站装的 nginx 那一段是不是最新的；记过网站的地址的，再经过网站查一下接口 |
| `./deploy.sh verify [https://网站的地址] [--via 127.0.0.1]` | 经过网站把页面、脚本、接口、联机、后台访问一遍，不对的说该查什么；全对退出码是 0。地址记过一次以后可以不写 |
| `./deploy.sh stop` / `restart` | 停、重启（停的时候会先把数据写回磁盘） |
| `./deploy.sh logs` / `logs -f` | 看最近的日志 / 一直跟着看（不会自己结束） |
| `./deploy.sh service` | 装成 systemd 服务：开机自启，挂了自动拉起（要 sudo）。装了以后 stop、status、logs 都走 systemd；要换端口、数据目录，带上参数再装一次（`./deploy.sh service --port 8080`） |
| `./deploy.sh nginx` | 重新生成、打印 nginx 那一段和装的步骤；看网站装的是不是最新的 |
| `./deploy.sh uninstall` | 撤掉：停下，拆掉这个目录装的 systemd 服务；代码、数据、备份留着，列出来让你决定删不删 |
| `./deploy.sh backup` | 把数据目录打包到 `backups/` |
| `./deploy.sh restore backups/data-….tar.gz` | 用一份备份恢复（先停、恢复、再启动） |
| `./deploy.sh reset` | 清空店里的数据（名册、抽奖登记、抽奖记录、计数），保留后台口令；先自动备份一份，要输入 RESET 确认（不能打字的，见"给执行部署的 agent"第 10 步的写法） |
| `./deploy.sh pack` | 打离线包，见下面 |
| `./deploy.sh check` | 只检查 Node、数据目录和端口 |

**更新代码**：见上面"给执行部署的 agent"的"升级"。只改了网页（`index.html`、`js/`），刷新浏览器就行：服务端发网页时不缓存。

## 离线包：内网服务器上不了外网

在能上网的电脑上：

```
./deploy.sh pack                                       # 只有代码
./deploy.sh pack --with-node node-v20.17.0-linux-x64.tar.xz   # 连 Node 一起（服务器是 Linux x64）
```

打出来的是 `dist/1024-cat-cafe-日期.tar.gz`：网页、代码、像素字体（`fonts/`）、服务端、文档、`deploy.sh`；带了 `--with-node` 的，Node 解在包里的 `runtime/node`，服务器上不用另装。默认不带 `config.js`（里面有内网地址），要带就加 `--with-config`。

拷到服务器上：

```
tar xzf 1024-cat-cafe-日期.tar.gz && cd 1024-cat-cafe-日期
./deploy.sh --data ~/1024-cat-cafe-data --inner 'https://内源主页的地址'
```

Node 的二进制包从 Node 官网或公司的软件源下，选和服务器一致的系统和架构（多半是 linux-x64）。

## 不用脚本

`deploy.sh` 只是包了一层，手动也一样：

```
cd A-像素猫咖
PORT=1024 HOST=127.0.0.1 TRUST_PROXY=1 node server/server.js
```

nginx 那一段照上面的装（`./deploy.sh nginx` 也能只生成它，不启动）。

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 1024 | 端口 |
| `HOST` | 127.0.0.1 | 监听地址 |
| `DATA_DIR` | `server/data` | 数据目录 |
| `TRUST_PROXY` | 0 | 挂在 nginx 后面要设 1（`deploy.sh` 固定设 1） |
| `ADMIN_KEY` | 读 `admin.key` | 指定后台口令（不写就用数据目录里生成的）。只对手动启动有用：`deploy.sh` 和装成的服务不会把它传给服务端，要固定口令就写进 `admin.key`（见下面"配置项一览"） |

开在终端里时，启动的那一行会打印后台口令；放在后台（nohup、systemd）时只写口令在哪个文件。

**Windows**：装好 Node，在 `A-像素猫咖` 目录里用 PowerShell：

```
$env:PORT=1024; $env:HOST='127.0.0.1'; $env:TRUST_PROXY=1; node server\server.js
```

要开机自启，可以用 NSSM 这类工具把这一行装成服务。

## 配置项一览：在哪儿改、改了怎么生效

一共五处能配：`deploy.sh` 的参数、服务端的环境变量、网页的 `config.js`、数据目录里的口令文件、网址后面的 `?dev`。另有一些只在代码里的常数，列在最后。挂的路径 `/1024-cat-cafe/` 是固定的，也在最后。

**1. `deploy.sh` 的参数**（记在 `deploy.env`，下次 `start`、`restart`、`service` 沿用；`deploy.env` 不进仓库）

| 参数 | 默认 | 改了怎么生效 |
|---|---|---|
| `--port` | 1024 | `./deploy.sh restart --port 8080`；装成服务的用 `./deploy.sh service --port 8080` 再装一次。nginx 那一段跟着重新生成，照 `status` 给的命令更新网站装的那一份 |
| `--host` | 127.0.0.1 | 同上。只有 nginx 在另一台机器上才改 |
| `--data` | `server/data` | 同上。换目录不会搬数据：先 `backup`，换了以后 `restore` |
| `--inner` | 空 | 写进 `config.js`；服务在跑也行（`./deploy.sh start --inner …`），刷新页面生效 |
| `--bots` | 40 | 同上 |
| `verify` 后面的网站地址、`--via` | 空 | `verify` 记进 `deploy.env`（`SITE`、`VIA`），以后 `verify`、`status` 都用它 |
| `pack --with-node 包` | 不带 | 离线包里连 Node 一起放 |
| `pack --with-config` | 不带 | 离线包里带上 `config.js`（有内网地址，别外传） |
| `logs -f` | | 一直跟着看日志 |

以前的 `--proxy` 现在固定开着（猫咖总在 nginx 后面），写了也不报错。

**2. 服务端的环境变量**（不用脚本、手动 `node server/server.js` 时用；`deploy.sh` 按上面的参数替你设好前四个）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 1024 | 端口 |
| `HOST` | 127.0.0.1 | 监听地址 |
| `DATA_DIR` | `server/data` | 数据目录 |
| `TRUST_PROXY` | 0 | 设 1：按 nginx 加在 `X-Forwarded-For` 最后的那个地址认人 |
| `ADMIN_KEY` | 读 `admin.key` | 后台口令；只对手动启动有用 |

改了要重启服务端。

**3. 网页的 `config.js`**（放在 `A-像素猫咖/` 下，和 `index.html` 同一层；不进仓库，仓库里是 `config.example.js`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `api` | `'api'` | 接口地址。相对地址，挂在 `/1024-cat-cafe/` 下不用改；空着就是本机模式（只有机器人，名册存在浏览器里，不能登记抽奖） |
| `ws` | 不写 | 联机地址。不写就用页面所在路径下的 `ws`（`wss://网站的地址/1024-cat-cafe/ws`）；只有联机要走另一个地址时才写 |
| `bots` | 40 | 补位的机器人：这个数减去在线真人数，最少留 12 只（`bots` 本身不到 12 就按 `bots`） |
| `links.inner` | 空 | 内源主页（内网地址）；没配的话点了提示"地址还没配"，章照样盖 |
| `links.site`、`docs`、`github`、`issues`、`releases`、`tips`、`concierge`、`evidence` | 公开地址 | 官网、文档、仓库、提 issue、下载安装包、使用小 Tips、两篇设计文档。默认地址在 `js/quest-bank.js` 的 `LINKS` 里；内网有镜像、上不了外网时可以换掉 |

改了刷新页面就生效，不用重启服务端（服务端发网页不缓存）。没有这个文件也能开：内置服务端会现给一份 `{api:'api'}`。

**4. 数据目录里的文件**（默认 `server/data`，网页请求拿不到，也不进仓库）

| 文件 | 说明 | 怎么改 |
|---|---|---|
| `admin.key` | 后台口令，一行 | 想换：改这个文件，或者删掉让它下次启动重新生成；然后重启。装成服务的也这样改 |

## 数据和个人信息

- 数据目录里两个文件：`cats.json` 是名册、店里的计数、抽奖登记和抽奖记录；`admin.key` 是后台口令。目录只有这个账号能读，不对外发（网页请求拿不到），也不进仓库。

## 出了问题

先跑 `./deploy.sh verify`：它挨个访问一遍，不对的那一行下面 `→` 写着该查什么。

| 现象 | 看什么 |
|---|---|
| `端口 1024 被占了` | 换一个：`./deploy.sh start --port 8080`，再照 `status` 给的命令更新网站装的那一段 |
| verify：`连不上 https://…` | 服务器上解析不了、或者走不到网站的域名：加 `--via 127.0.0.1` 直接连本机的 nginx |
| verify：`/1024-cat-cafe/` 是 404 | 那一段没生效：include 那一行加在网站对外的 server 里了吗（不是只做跳转的那个）？`nginx -t`、reload 了吗？`sudo nginx -T` 的输出里搜得到 `1024-cat-cafe` 吗？ |
| verify：502 | 猫咖没在跑（`./deploy.sh status`）；或者网站装的那一段端口和猫咖的不一样（`status` 会说"不一样"）；都对的话看 nginx 的 error.log：有 `(13: Permission denied) while connecting to upstream` 是 SELinux 不让 nginx 连这个端口（CentOS、RHEL 上常见）。改 SELinux 是改系统的安全设置，问服务器的负责人；只放行这一个端口的做法是 `sudo semanage port -a -t http_port_t -p tcp 1024` |
| verify：脚本 404 或"不是猫咖的" | 那一段里 location 后面的 `^~` 丢了 |
| verify：带上了网站的 Content-Security-Policy | 那一段里 `add_header` 那一行丢了；浏览器里的样子是停在"开门……"白屏 |
| verify：`/1024-cat-cafe/` 是 302、401、403 | 网站整站要登录，见"网站的 server { } 里，这几样也会管到" |
| verify：联机不是 101 | 那一段里 `Upgrade`、`Connection` 两行；verify 加 `--via 127.0.0.1` 是 101、不加就不是：网站前面还有一层负载均衡或者 WAF 不放行 WebSocket，找管网络的人 |
| 网站的 nginx 跑在容器里（`docker ps` 里有 nginx） | 容器里的 127.0.0.1 不是这台机器：停下问人（要把那一段里的地址换成宿主机的、猫咖用 `--host` 听那个地址） |
| 加载到一半有 503 | 网站开了 `limit_req`，见"网站的 server { } 里，这几样也会管到" |
| 进得了店，看不到别人 | 同"联机不是 101"；`proxy_read_timeout` 太短的话，过一会儿就断开、又连上 |
| 换了个地址打开，猫和章都没了 | 令牌是按网站的地址存在浏览器里的，换回原来的地址就在；见"定下网站的地址再开张" |
| `数据目录 … 里有不是猫咖的东西` | `--data` 指到了放着别的文件的目录：给猫咖单独建一个空目录 |
| `cat1024.service 已经有了，不是猫咖装的` | 服务器上有个同名的服务，别覆盖它：改 `deploy.sh` 开头的 `UNIT` 换个名字再装 |
| 后台口令忘了 | `./deploy.sh status` 会打印；或者看数据目录里的 `admin.key`。想换一个：改这个文件（或者删掉它，下次启动重新生成一个），再 `./deploy.sh restart` |
| 后台说口令错太多次，可没人输错 | 网站前面还有一层负载均衡时，大家在猫咖看来是同一个地址，谁输错都算在一起：等 10 分钟 |
| 十秒内没起来 | `./deploy.sh logs` |
| 服务器重启后没了 | 没装成服务：`./deploy.sh service` |

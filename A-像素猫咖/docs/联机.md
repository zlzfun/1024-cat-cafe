# 联机

店里别的猫，以前全是机器人。接上服务端以后，同时在线的人能在店里看到彼此：谁在哪儿走、窝在哪儿、叼着什么、冒了什么表情、说了哪句快捷短语；可以互相蹭蹭、传毛线球。人少的时候，仍由机器人补位。

本机模式（没有服务端）不联机，和以前一样。

## 一、看得到什么、能做什么

| | 联机以后 |
|---|---|
| 别的真人的猫 | 在它真正的位置上，走路、跳上家具、窝着、睡觉、玩毛线球的姿态都跟着它主人的画面走，大约晚 0.3 秒 |
| 表情（数字键） | 附近的猫都看得到冒出来的表情；三只猫 4 秒内一起喵，照样触发喵喵合唱，真人和机器人一起算 |
| 快捷短语（T） | 头上冒一句。只能说那八句固定的话，没有自由打字 |
| 蹭蹭 | 对真人的猫也能蹭，两边都冒一颗心，对方收到"某某蹭了蹭你" |
| 传毛线球 | 能传给真人。对方嘴空着就接住，便签（同一道题）在对方那边展开，球权链从"门外 → 你 → 它"接着记；嘴里有东西，球滚回来。对方织好挂进橱窗时，你会收到一句"某某把你传的毛线球织成了一顶毛线帽" |
| 请真人 review | 走流程那道题的 Review 一步，可以把球传给真人的猫：它看一眼，球就回到你嘴里，这一步算过。对方什么都不用做，画面上会看到"某某请你看一眼它的代码" |
| 挂进橱窗 | 别人挂的成品也会出现在你这边的橱窗里，等人类来取 |
| 毛线巨树 | 全店共同的进度：所有真人挂进橱窗的成品都挂到同一棵树上，大家看到的是同一棵树；挂满 36 件的那一刻，所有人一起看到满树金光 |
| 小黑板 TODAY | 今天全店真人一共挂了几件；每满 10 件、50 件，全店一起庆祝 |
| 左上角 | "店里 46 只猫 · 在线 12"：前一个数包括补位的机器人和店猫，后一个是此刻在线的真人 |
| 新闻 | 真人上线会出现在左下角的新闻里（人多时会省略一部分） |

**各算各的**：店里其余的东西仍在每个人自己的画面里运行，包括门口来的毛线球、毛线篮、店猫在做什么、机器人、大毛线团、零食机、CI 灯和拍照。真人之间一起玩多猫装置，留到以后再做（见最后一节）。

## 二、机器人补位

- 补位的数量 = `config.js` 里的 `bots`（默认 40）减去在线真人数，但最少留 12 只（`bots` 本身不到 12 就按 `bots`），这样"几只猫一起"的毛线球总有帮手。有真人进店，就有一只机器人从入场纸箱里钻出去；真人走了，再补一只回来。
- 机器人只在各自的画面里，每个人看到的机器人不一样。真人的名字全店唯一，机器人如果和某个真人同名，会自己改名。
- 店猫（宪宪、砚砚……）和前台猫在每个人的画面里都有，也是各演各的。

## 三、怎么连

浏览器和服务端之间是一条 WebSocket（`/ws`），和网页同一个地址。服务端仍然零依赖，WebSocket 的握手和收发由 `server/ws.js` 自己实现。

1. 进店（掉下来或醒来）以后开始连，第一条消息带上令牌。
2. 服务端核对令牌，回一份"现在谁在线、各自在哪儿"和巨树、小黑板的计数。
3. 浏览器报一次自己的画面有多大（换窗口大小、按 Z 缩放时再报），之后每 0.15 秒看一次自己的猫有没有变化，变了才发。
4. 服务端每 0.1 秒给每个人发一包：
   - 他画面里的猫（按他报的画面大小算，镜头到了地图边上会停住，这一点也照着算；四周再多留一圈），凡是比他上次收到的新，就发一份完整状态。三层楼画在同一张大图上、上下隔得很远，别的楼层的猫不会落进他的画面；
   - 画面外的猫每秒只发一次位置，给小地图用；
   - 一只猫走进画面的那一刻，缺的完整状态在下一包里补上。
5. 断线后自动重连：1、2、4、8……最多隔 30 秒试一次。断着的时候，真人的猫先停在原地，10 秒后消失，机器人补回来。

**同一只猫只能在一个地方**：同一只猫从第二个地方连上来，先连的那个会收到"它在另一个窗口里醒着"，和同一台电脑上开两个窗口是一样的处理。

### 猫的状态

一只猫的状态是一个数组：

`[x, y, z, dy, 姿态, 朝向, 表情脸, 叼着什么, 标志位]`

- `z`：站在家具上时的高度（决定前后遮挡），在地上是 `null`；`dy`：跳起来的高度。
- 叼着什么：`0` 什么都没有；`y3` 一颗 3 号色的毛线球；`hat:2` 一顶织好的 2 号色毛线帽（成品有 scarf、hat、mitten、sock、sweater、flag）；`t:mouse` 叼着桌上的小东西（pen、globe、mouse、cactus）。
- 标志位：1 藏起来了（钻纸箱、钻隧道），2 镜像。

收到的状态先放进一个小缓冲，画的时候取 0.25 秒以前的两份，位置按时间插值，姿态和表情取前一份。一只猫停了很久再动，它的第一份新状态前面会补一份"刚才还停着"，免得它从很远慢慢滑过来。两份之间差了 200 像素以上（比如刚醒来、刚掉下来），直接跳过去。

### 消息

浏览器发给服务端：

| 消息 | 说明 | 限制 |
|---|---|---|
| `{t:'hi', token}` | 第一条，报身份 | 5 秒内不发就断开 |
| `{t:'v', v:[宽, 高]}` | 自己的画面有多大（世界像素） | 每 0.5 秒最多 1 条 |
| `{t:'s', s:[...]}` | 自己的猫的状态 | 每秒最多 14 条 |
| `{t:'emo', i}` | 表情，0～7 | 每秒最多 2 条 |
| `{t:'ph', i}` | 快捷短语，0～7 | 每秒最多 1 条 |
| `{t:'rub', to, k?}` | 蹭蹭某只猫；`k` 是别的几种猫和猫的互动：`groom` 舔舔毛、`boop` 碰碰鼻子、`play` 一起玩、`nap` 挨着睡（见[店内设计](店内设计.md)第五节） | 对方得在 60 像素以内；`k` 只认这四个词，别的当作蹭蹭 |
| `{t:'pass', to, p, ball:{ci, kind, qid, rv?}}` | 传球；`p` 是这一次传球的编号，`rv` 表示请对方 review | 对方得在 200 像素以内 |
| `{t:'got', to, p}` | 接球的一方：接住了 | 只认这笔传球的接球方 |
| `{t:'back', to, p, ok?}` | 接球的一方：腾不出嘴，还回去；review 的球带 `ok:1` 表示看过了 | 同上 |
| `{t:'hang', kind, ci, from?}` | 自己挂进橱窗一件；`from` 是这颗球传过来的那只猫 | 每 2.5 秒最多 1 次 |

服务端发给浏览器：

| 消息 | 说明 |
|---|---|
| `{t:'welcome', id, me, cats, world}` | 连上了：`me:{name, prizes}` 是自己此刻的名字和还没看过的中奖通知（断线期间被改名、中奖，重连时补上）；在线的猫 `[{id, n, name, look, s}]`；`world:{hung, day, today, tree}`。`n` 是这条连接的短编号，下面高频的几样用它代替猫的 id |
| `{t:'b', u, p, j, l}` | 一包变化：`u` 完整状态 `[[n, s], ...]`，`p` 画面外的猫的位置 `[[n, x, y], ...]`，`j` 新来的猫，`l` 走了的猫的 `n` |
| `{t:'emo', id, i}`、`{t:'ph', id, i}` | 某只猫冒表情、说快捷短语 |
| `{t:'rub', id, to, k?}` | 某只猫蹭了（或者舔毛、碰鼻子、找来玩、挨着睡）另一只 |
| `{t:'pass', id, p, ball}` | 有猫把球传给你 |
| `{t:'toss', id, to, ci}` | 附近有猫把球传给别的猫（只为了画那道弧线） |
| `{t:'got', id, p}` | 你传的球，对方接住了 |
| `{t:'back', id, p, ball, why}` | 你传的球回来了：`why` 是 `busy` 对方腾不出嘴、`gone` 对方不在了或 20 秒没回应、`reviewed` 对方看过了 |
| `{t:'woven', id, kind, ci}` | 你传出去的球，被对方织好挂上了 |
| `{t:'hang', id, kind, ci, hung, day, today}` | 有猫挂了一件：巨树加一件，计数更新。小黑板同一天里只往上涨，`day` 变了（过了午夜）就直接换成新的数 |
| `{t:'rename', id, name}` | 组织者给某只猫改了名 |
| `{t:'prize', ...}` | 你被抽中了（见[组织者后台](组织者后台.md)） |
| `{t:'bye', why}` | 服务端要断开：`elsewhere` 在别处连上了、`ban` 被封禁、`auth` 令牌无效 |

## 四、安全

- **身份只认令牌**：名字、长相都由服务端按令牌对应的猫填进去，浏览器发来的消息里不带名字。
- **不传任何自由文字**：快捷短语只传序号，毛线球只传题号（`qid`），收到的一方从自己的题库里取便签。球权链在对方那边从"门外 → 传球的猫 → 你"重新开始。所以没有办法借联机给别人发任意的字。
- **每样字段都查**：坐标得在地图里；姿态、表情脸得是 `js/cat-sprites.js` 里真有的（服务端启动时读这个文件）；颜色、成品种类、表情、短语序号都在范围内。不对的消息直接丢掉，浏览器收到的状态也再按同一份表查一遍。
- **出错只断一条**：处理某条消息时出了任何错，只断开发这条消息的连接，服务端和别人不受影响。
- **传球是事务**：服务端记着每一笔"谁传给谁"。只有接球的那只能回"接住了"或"还回去"，别的猫伪造不了回球；接球的下线或 20 秒没回应，球退给传球的。接球的一收到就回话，不等飞行动画；球在半路时嘴里有了别的，球落进门口的毛线篮。所以一颗球不会变成两颗，也不会凭空消失。
- **离店就断**：离店作废了令牌，用这张令牌连着的联机通道也一起断开。
- **限速**：每条连接每秒最多 30 条消息、每条最多 2KB；超了先丢，连续超就断开。底下的帧也有预算（每秒 60 帧，心跳帧也算），刷心跳也会被断开。
- **封禁**：组织者封禁一只猫，服务端立刻把它断开，它的令牌全部作废。

## 五、容量

真人的猫只在画面附近的人那里是"高频"的，所以每个人收到多少，主要看自己画面里有几只猫在动，和总人数关系不大。实测见第七节：

| 同时在线 | 每个浏览器收 | 服务端发出 | 服务端 CPU | 内存 |
|---|---|---|---|---|
| 100 只 | 约 11～12KB/秒 | 约 1.2MB/秒 | 一个核的 2% | 66MB |
| 200 只 | 约 23～25KB/秒 | 约 5MB/秒 | 一个核的 5% | 87MB |

每个浏览器每秒发 4～5 条状态（在走路时），约 0.3KB/秒。

## 七、压力测试

```
DATA_DIR=/tmp/cat-load PORT=1025 node server/server.js      # 用一个临时的数据目录，别写进正式名册
DATA_DIR=/tmp/cat-load node server/loadtest.js http://127.0.0.1:1025 100 60   # 100 只猫，跑 60 秒
```

压力测试要 Node 22 以上（自带 WebSocket）。它登记 N 只叫"压测001"这样的猫，每只都和浏览器一样：每 0.15 秒看一次、变了才发，在店里几块空地之间走，停下来歇 2～12 秒；隔一阵冒个表情、说句短语、蹭蹭或者传球给身边的猫、挂一件成品。画面大小在几种常见窗口里随机。带上 `DATA_DIR`（或 `ADMIN_KEY`），还会读服务端自己的 CPU、内存和打包耗时。

2026-09-29 在一台 Mac 上（服务端和假玩家在同一台机器；按检视意见修完以后重测）：

| | 100 只猫，60 秒 | 200 只猫，40 秒 |
|---|---|---|
| 每只猫每秒发 | 4～5 条 | 4～5 条 |
| 每只猫每秒收 | 12～13 条，约 11～12KB | 17～20 条，约 23～25KB |
| 延迟（一只猫动了到别人收到） | 中位 40～55ms，99% 约 105ms | 中位 55～75ms，99% 约 110～125ms |
| 服务端 CPU / 内存 | 2% / 66MB | 5% / 87MB |
| 每 0.1 秒打包一次花 | 约 1ms | 约 3ms |

延迟里包含服务端 0.1 秒一次的打包间隔；浏览器那边再加上 0.25 秒的插值缓冲，看上去大约晚 0.3 秒。一只停了很久的猫走进画面时补发的那份状态，不算在延迟里。

## 八、以后

- **一起玩多猫装置**：大毛线团、零食机三爪垫、喵喵合唱以外的协作装置，现在各算各的。要做成真人一起，得让服务端来安排大毛线团什么时候来、谁站在哪块爪垫上。
- **更多人**：一个进程带一两百人没问题；再多要按房间分组转发，或者开几个进程分店。

# 1024 现场抽奖

2026-10-23（周五）线下活动用的抽奖，在会场的一台电脑上单独跑。和"1024 猫咖"那个小游戏、店里的集章登记抽奖都不相干：奖品、记录、数据都是自己的。扭蛋机的动画、像素字和配色借猫咖的（`../A-像素猫咖/` 里的几个文件），所以要和猫咖放在同一个仓库目录里。

## 现场怎么抽

1. 工作人员先确认这个人满足条件（关注内源社区、猫猫观察局，加入猫猫群，或者参加了互动游戏……），系统不管这一步。
2. 工作人员点"抽一次"（或者按空格）。扭蛋机转一圈，扭蛋蹦出来、晃三下、裂开，当场出结果。
3. 抽到**一、二、三等奖**（虚拟奖品）：当场登记工号。登记好了，活动结束后组织方按工号统一联系兑奖。
4. 抽到**谢谢惠顾**：当场发一张猫猫图鉴卡（卡很多，不记库存）。

中了奖不登记工号，就抽不了下一次：免得人走了工号没留。真的登记不了（比如这个人不要了），点"作废"，这份奖品放回奖池。

同一个工号之前中过，登记时页面会提醒"W001 之前中过二等奖"，由工作人员决定：还是登记，或者作废这一次。

**只有一台抽奖台。** 同一时间只有一台（一个浏览器标签页）能抽、能登记、能作废；别的设备再打开抽奖页是**观看**：跟着演那一幕、显示结果（不显示工号），没有按钮，适合投到大屏上。
- 第一个打开的就是抽奖台。抽奖台的页面关掉了，下一个新打开的页面过 10 秒自己接手；也可以在观看页上点"在这台抽"，原来那台变成观看。
- 中了奖没登记就关掉了页面，接手的那台打开就是那一次的登记表，接着登记或者作废。
- 声音每台各记各的，比如抽奖台关掉、大屏开着。

**断线了不会多抽，也不会漏掉结果。** 每按一次"抽一次"带一个编号；连不上会自己重试，再按也是同一个编号，服务端抽过的就把那一次原样还回来。回复丢了的那一次是谢谢惠顾，连上以后条上会补一句"第 N 次（断线时抽的）· 请发一张猫猫图鉴卡"。连不上时右下角变红"连不上抽奖服务"。

## 抽奖的那一幕

抽奖页上面整块是舞台，给围观的人看；下面一条是工作人员的操作条（登记工号、作废、下一位）。

舞台：深紫的后墙，两边红幕，右上一块跑马灯招牌"1024 扭蛋抽奖"，两盏追光来回扫；正中一台很大的猫头扭蛋机（猫咖进店时那台）；台下一群猫，两边坐着看，前排是背影。左边墙上挂一块奖品榜：每一档的图片和名称，最后一行是谢谢惠顾的猫猫图鉴卡；不写还剩几份（还剩几份只在设置页看）。

按一下空格：

1. 猫群齐刷刷冒"!"转过头来，灯暗下来、追光打在扭蛋机上，旋钮咔哒咔哒转一圈，机器跟着抖。
2. 扭蛋从出蛋口滚出来，蹦到聚光灯里，变得很大。扭蛋的颜色是随机的，不透露结果。
3. 像宝可梦收服那样：晃一下、停住，晃一下、停住……停住的时候猫群瞪大眼睛、头上冒省略号。
4. **中了**：晃满三下，"咔哒"一下冒一圈星星，然后"叮咚"！白光一闪，扭蛋裂开，奖品卡跳出来：上面是奖品的图片，下面是几等奖（一等奖金色、二等奖蓝色、三等奖赤陶色，和奖品海报一套）和奖品名，猫群蹦起来欢呼、冒音符和爱心，两边像炮筒一样喷彩带。
5. **没中**：晃一到三下就裂开，冒一团灰烟，卡片上是图鉴卡的图片和"谢谢惠顾 · 送你一张猫猫图鉴卡"，猫群一起叹气（哭脸、汗滴，有一只直接趴下）。

中奖从按下到能登记工号大约 7 秒，没中 5～6 秒；欢呼和彩带在登记的时候接着放。系统开了"减少动态效果"，结果一回来就直接揭晓。声音默认开着，操作条右边有开关。

声音是真录音（来源和许可见 `snd/来源.md`，都是 CC0 或公有领域）：转旋钮咔哒咔哒，扭蛋骨碌碌滚出来；落进聚光灯后鼓点开始滚奏，越晃越响，揭晓那一刻一刀切断。中了是"叮"一声、钢鼓一串往上走、彩带炮"砰砰"、台下欢呼鼓掌，几只猫跟着叫，一等奖最热闹；没中是萨克斯"哇～哇～"往下滑，台下一声"哦～"，两只猫低低地叫。哪段录音没加载上，就退回猫咖那套合成音。

## 启动

要装 Node.js 18 以上（不用装任何别的包）。

```bash
cd B-现场抽奖
node server.js
```

浏览器打开它打印出来的地址（默认 `http://127.0.0.1:1025/`）。Windows 上也可以双击 `启动.bat`，macOS 上双击 `启动.command`。

| 页面 | 地址 | 给谁用 |
|---|---|---|
| 抽奖 | `/` | 现场：抽、登记工号、作废；浏览器全屏放着（F11），有投影就投上去 |
| 设置 | `/admin.html` | 活动前配奖品和图鉴卡；活动中看记录、补货、暂停；活动后导出 |

只有这台电脑自己打得开（服务只听 `127.0.0.1`），所以不设口令。想让会场别的设备也打开（大屏观看、设置页）：`HOST=0.0.0.0 node server.js`，这时候同一个局域网里谁都能打开，自己掂量。

Windows 的老式黑窗口里，鼠标点一下会进"选择文字"模式，服务就卡住了（抽奖页右下角变红"连不上"），按一下 Esc 就好。`启动.bat` 把服务开在一个叫 `lotto-1024` 的新窗口里，给这个窗口关掉了这个模式。

## 奖品和概率

设置页里配，每一档：

| 项 | 意思 |
|---|---|
| 等级 | 一、二、三等奖 |
| 名称 | 奖品本身，比如"定制机械键盘"（等级另外显示，不用写进名称） |
| 概率 | 百分数，最多两位小数：填 1 就是每次抽有 1% 的机会中这一档 |
| 库存 | 有几份；空着是不限 |
| 图片 | 点"上传图片"选一张 png、jpg、webp；浏览器先缩到最长边 640 再传上来。舞台左边的奖品榜、中奖时跳出来的卡片都用它。没传的用等级的颜色写"壹 / 贰 / 叁"占着 |

猫猫图鉴卡的图片在设置页"现场"那一块传，谢谢惠顾的卡片和奖品榜最后一行用它。

**每次抽都独立**：一等奖填了 1%，每个人抽的时候都是 1%，不管前面的人抽到了什么。各档的概率加起来不能超过 100%，剩下的就是谢谢惠顾。比如一等奖 1%、二等奖 5%、三等奖 10%，谢谢惠顾就是 84%。

**某一档发完了**：它那份概率直接算谢谢惠顾，不匀给别的奖。上面的例子里一等奖发完以后，谢谢惠顾变成 85%，二、三等奖还是 5% 和 10%。所有奖品都发完了也照样能抽，抽到的都是谢谢惠顾；抽奖页和设置页会写出来。

**猫猫图鉴卡**：抽到谢谢惠顾就发一张。卡很多，不记库存，设置页只数发了几张。

**暂停**：设置页一个开关，暂停时抽奖页点不了"抽一次"。

## 数据和备份

- 都在 `data/lotto.json`（不进仓库）；奖品图片在 `data/images/`（换图以后旧的删掉）。每抽一次、每登记一个工号，都当场写进磁盘再回页面：页面上看到"一等奖"，记录就已经存好了。
- 每抽 20 次，`data/backups/` 里多存一份（只备份 `lotto.json`，图片不在里面，换电脑时把 `data/images/` 一起拷走）。
- 设置页的"清空重来"（彩排完用）：先把现在的存一份到 `data/backups/`，再清掉所有抽奖记录（图鉴卡的计数跟着清零）、把库存的"已发"归零；奖品设置留着。
- 活动结束：设置页"导出中奖名单"（工号、几等奖、奖品、时间，Excel 打开不乱码），交给兑奖的同事。

## 规则的细节

| 事 | 怎么处理 |
|---|---|
| 抽到什么 | 服务端用加密随机数按概率抽；页面只负责演动画 |
| 中了奖还没登记 | 不能抽下一次（`pending`），抽奖页一直停在登记那一步；在设置页里登记或者作废了，抽奖页两秒内跟上 |
| 抽奖台 | 抽奖页请求带 `X-Desk`（每个标签页一个编号）；抽、登记、作废只认抽奖台，别的回 409 `desk`。只记在内存里，服务重启后谁先打开谁是；设置页不带 `X-Desk`，不受限制 |
| 同一个编号抽两次 | 抽奖页每一次带 `req`；服务端见过这个编号就把那一次原样还回来（`again`），不再抽 |
| 工号的格式 | 字母、数字、`-`、`_`，2～32 位；去掉空格、转大写以后比较 |
| 同一个工号又中了 | 提醒，带上之前中的是第几次、几等奖；工作人员点"还是登记"才登记 |
| 登记错了 | 设置页的记录里能改工号 |
| 作废 | 只有中奖的能作废；放回库存，这一次记成"作废"，导出的中奖名单里没有它 |
| 认不出的等级 | 奖品只有 1～3 等；别的不收。记录里 0 是谢谢惠顾 |
| 旧版的数据（按权重抽、谢谢惠顾也是一档、图鉴卡有库存） | 读进来时谢谢惠顾那一档去掉，没有概率的当 0，在设置页里补上 |
| 读 `lotto.json` 读坏了 | 服务起不来，不会当成空的接着写（那会把记录盖掉）；用 `data/backups/` 里最近的一份换回来 |

## 接口

都只在本机。失败回 `{err}`：`closed` 暂停中 · `pending` 有中奖还没登记（带 `no`）· `sum` 各档概率加起来超过 100% · `bad` 参数不对 · `dup` 这个工号中过（带 `prev`）· `none` 没有这一次 · `desk` 这台不是抽奖台 · `disk` 没存上。

| 接口 | 请求 | 返回 |
|---|---|---|
| `GET /api/state` | — | `{open, note, cardImg, prizes, cards, lose, allOut, pending, recent, desk}`：`desk` 是 `{me 这台是不是抽奖台, has 有没有抽奖台, ago 抽奖台几秒前来过}`；奖品带 `rest` 还剩几份；`cards` 发了几张图鉴卡；`lose` 此刻谢谢惠顾的概率；`allOut` 奖品都发完了 |
| `POST /api/draw` | `{req}` | `{draw, again?}`：`{no, tier, name, card}`；`tier` 是 0 就是谢谢惠顾，`card` 是发图鉴卡；`again` 是同一个 `req` 又来了 |
| `POST /api/desk` | — | `{desk}`：这台（`X-Desk`）当抽奖台 |
| `POST /api/claim` | `{no, emp, force}` | `{draw}`；同工号中过、没带 `force` 回 409 `dup` |
| `POST /api/void` | `{no}` | `{draw}` |
| `GET /api/draws` | — | 全部记录，最新的在前 |
| `POST /api/prize` | `{id?, tier, name, prob, stock}` | 没有 `id` 是新加，有是改；库存不能改得比已经发出去的少；各档概率加起来超过 100% 回 `sum` |
| `POST /api/prize/del` | `{id}` | 只有一份都没发出去的能删（图片一起删） |
| `POST /api/image` | `{id, data}` | 传图：`id` 是奖品的，或者 `card`（图鉴卡）；`data` 是 `data:image/png｜jpeg｜webp;base64,…`，最大 2.5MB，文件头对不上的不收。图片发在 `/img/文件名` |
| `POST /api/image/del` | `{id}` | 删图 |
| `POST /api/restock` | `{id, n}` | 补 n 份 |
| `POST /api/settings` | `{open?, note?}` | 暂停开关、抽奖页上的一句提示 |
| `POST /api/reset` | — | 先备份，再清空记录 |
| `GET /api/export?what=won｜all` | — | CSV |

## 代码

| 文件 | 做什么 |
|---|---|
| `core.js` | 规则：按固定概率抽、发完的算谢谢惠顾、登记、重复提醒、作废。不读写文件，有测试 `core.test.js` |
| `server.js` | 零依赖的 Node 服务：接口、写盘、备份、发网页（借猫咖的几个文件） |
| `index.html`、`desk.js` | 抽奖页：舞台 + 下面的操作条 |
| `admin.html`、`admin.js` | 设置页 |
| `sfx.js`、`snd/` | 现场音效：每一步放哪几段录音、鼓点滚奏、欢呼和猫叫怎么错开 |
| `stage.js` | 舞台和那一幕：背景、招牌、追光、扭蛋机、悬念、观众、彩带（奖品榜和奖品卡是 `index.html` 叠在上面的，图片才清楚） |

测试：`node --test`（在这个目录里跑）。
